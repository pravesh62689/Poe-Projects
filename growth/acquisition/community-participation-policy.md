# Community Participation Policy & Ethical Engagement Guidelines

**Scope:** Developer forums, Reddit (`r/learnprogramming`, `r/SQL`, `r/regex`), Discord, Stack Overflow, GitHub discussions.  
**Mandate:** Protect brand integrity, avoid anti-spam penalties, and maintain 100% technical helpfulness.

---

## 1. Absolute Prohibitions

1. **No Automated Bot Posting:** Never utilize scripts or automated accounts to submit comments, replies, or threads.
2. **No Astroturfing or Sockpuppets:** Never create secondary accounts to post artificial praise or fake questions designed to mention the bots.
3. **No Unsolicited DMs:** Never send cold private messages to forum members.
4. **No Link-Only Dropping:** Never post a standalone link without delivering an exhaustive, self-contained technical explanation directly in the thread.

---

## 2. Standard Engagement Protocol

When responding to technical queries in community channels:

1. **Read & Understand the Specific Problem:**
   Verify if the user is asking about regex syntax, an SQL query error, or OCR extraction issues.
2. **Deliver the Complete Solution On-Platform:**
   Provide the working regex pattern, corrected SQL syntax, or explanation of character misrecognition directly in markdown within the forum post.
3. **Explain the Underlying Mechanism:**
   Explain *why* the solution works (e.g., greedy vs lazy quantifiers, SQL `LEFT JOIN` null handling).
4. **Optional Sandbox Link (Only If Helpful):**
   If interactive testing provides real value, include an unobtrusive disclosure:
   > *"If you want to test this regex against negative cases without setting up a test harness, I built a free sandbox tool on Poe ([Regex-Gen-Tester](https://poe.com/Regex-Gen-Tester)) that checks for ReDoS vulnerabilities."*
5. **Respect Community Rules:**
   Adhere strictly to subreddit self-promotion guidelines (e.g. 9:1 contribution ratio).
