## 1. Parent Brand Architecture

### Umbrella Positioning
> **"Verified practical AI tools for documents, patterns, and data."**

We are not an entertaining chatbot suite. We build specialized, deterministic developer and business intelligence utilities. Where generic LLMs hallucinate text, numbers, and code, our bots execute actual computer vision, real V8 regex compilation, and ephemeral SQLite database engines to verify every answer before the user sees it.

### Visual & Typographic Hierarchy (Per BRAND.md)
- **Studio Identity:** Modern, disciplined, high-density developer tool aesthetic.
- **Wordmark & Headlines:** Clash Display (Semibold/Bold, Indian Type Foundry) — signals modern, deliberate engineering.
- **Body & Interface:** Satoshi (Regular/Medium) — clean, high-legibility geometric sans-serif.
- **Code & Accents:** JetBrains Mono — developer credibility.
- **Color Palette System:**
  - Base Background (All Bots): `#0B0B0F` (Dark theme, 22% corner radius tile).
  - OCR-Doc-Bot Accent: Electric Indigo `#6366F1` (Precision, vision).
  - Regex-Gen-Tester Accent: Terminal Lime `#A3E635` (Execution, pattern matching).
  - English-To-SQL Accent: Data Cyan `#22D3EE` (Relational, analytical clarity).

## 2. Product Positioning Statements

### 1. OCR-Doc-Bot
- **Category:** Document Intelligence & Accounting Automation
- **Core Value Proposition:** *"Extract receipt and document details from images — with confidence flags, blur gating, and arithmetic verification."*
- **The Enemy:** Hallucinating LLMs that misread receipt totals and thermal fades without warning.
- **The Proof:** Pre-OCR Laplacian blur gate, projection deskewing, and exact $Subtotal + Tax = Total$ mathematical reconciliation.

### 2. Regex-Gen-Tester
- **Category:** Developer Tools & Pattern Validation
- **Core Value Proposition:** *"Generate, test, and inspect regex patterns against your own samples in real-time — with linear ReDoS safety proof."*
- **The Enemy:** AI chatbots that invent broken regex patterns with catastrophic backtracking bugs.
- **The Proof:** Live V8 isolate execution table with capture groups, microsecond execution benchmarks, and linear-time ReDoS analysis.

### 3. English-To-SQL
- **Category:** Relational Database Analytics & Learning
- **Core Value Proposition:** *"Turn schema + plain English into SQL, then run it against an in-memory database before you use it."*
- **The Enemy:** Unverified text-to-SQL tools that generate syntax errors, invent non-existent columns, or produce silent Cartesian products.
- **The Proof:** Real in-memory SQLite WASM execution showing returned data tables, self-correcting error recovery, and destructive statement warnings.

## 3. Ten Naming Options & Systematic Evaluation Matrix

Every name is evaluated on a 1–5 scale across 8 objective criteria:
1. **Search Clarity (SC):** Does it contain the primary keyword?
2. **Poe Discoverability (PD):** Does it rank well in Poe explore search?
3. **User Understanding (UU):** Does a first-time user know what it does immediately?
4. **Differentiation (DF):** Does it stand out from generic "AI Assistant" bots?
5. **Brevity (BR):** Is it memorable and under 18 characters?
6. **No Misleading Claims (NC):** Free of false "100% / Perfect / Magic" claims?
7. **Function Consistency (FC):** Exactly reflects actual technical execution?
8. **Trademark Safety (TS):** Zero risk of trademark conflicts (no "OpenAI", "ChatGPT", "Excel")?

## 4. Handle Migration & Redirect Protocol

Handles in Poe are **permanent URLs** (`poe.com/<Handle>`).
- If migrating from an existing live handle to a new optimized handle:
  1. Register the new optimized handle first.
  2. In the existing handle's introduction message, place a prominent top banner:
     `🔄 This bot has upgraded to @<NewHandle> with improved verification and latency. Please message @<NewHandle> directly.`
  3. Update all external landing pages, documentation links, and social mentions.
  4. Never abandon the old handle; maintain a keep-warm script so existing users receive the redirect prompt.
